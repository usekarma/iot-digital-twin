# Security policy

Do not disclose exploitable vulnerabilities or credentials in public issues. Use GitHub private vulnerability reporting when enabled, or contact the repository owner privately through an existing trusted channel. No response SLA is promised by this template.

Never commit real secrets or customer data. Revoke exposed credentials before removing them from history. Run all quality gates before publishing changes. Fix vulnerability audit findings or document a narrowly scoped reviewed exception through a deliberate policy change; the default gate has no bypass.

This template supplies basic static checks and a threat-model workflow, not a complete security assessment. Configure private reporting and security scanning for projects created from it.
